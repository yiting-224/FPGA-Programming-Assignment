Topology-Aware Multi-FPGA Partitioning

CS 516000 Programming Assignment — report

1. Overview

The partitioner assigns every node of a directed hypergraph to one of K FPGAs such that the total link cost (TLC) is minimised while the node capacities, the I/O limits and the link constraints (every sink FPGA of a signal must be directly linked to its source FPGA) are respected. The program is written in C++17 using only the standard library (including std::thread) and is built with make.

The approach combines three ideas:

  1. Multilevel partitioning (in the style of hMETIS / KaHyPar [1,2]): the hypergraph is coarsened by clustering, partitioned on the coarsest level, and projected back level by level with greedy refinement.
  2. Multilevel simulated annealing [3,4]: from the resulting partition a partition-preserving hierarchy is built and every level, from the coarsest to the finest, is annealed. Moves on the coarse levels move whole clusters, so the annealer can relocate entire communities between FPGAs, which single-node moves cannot do.
  3. Parallel multi-start: up to four worker threads run independent attempts with different random seeds and different annealing parameters; the best legal solution is written.

All cost and constraint evaluations are exact and incremental, so a move is evaluated in time proportional to the number of nets incident to the moved node.

2. Objective and constraint handling

For a net e with weight w(e), source FPGA s and set O(e) of FPGAs holding at least one sink, the cost is w(e)·Σf∈O(e)\{s} D(s,f), and if O(e)\{s} is non-empty the net uses w(e) I/O pins on s and on every FPGA of O(e)\{s}. The optimiser minimises

J = Σe w(e)·Σf∈O(e)\{s} D(s,f) + λ·Σf max(0, IO(f) − IOlimit(f))

where D(a,b) is the link cost and, for an unlinked pair, a large penalty B = max(10000, 1000·max cost). λ = B as well. The constraints are therefore handled as follows:

  • Capacity (both node types) is a hard constraint: a move is only applied if the target FPGA has room; when it has not, the annealer tries a swap instead (Section 4.2).
  • Link and I/O constraints are soft during optimisation with penalties that dominate every possible saving in link cost, so local search removes violations first. Solutions are compared lexicographically by (signals over missing links + I/O overflow, TLC); hence a legal solution is always preferred.
  • Assignment: every node receives exactly one FPGA by construction.

Parsing removes sinks that equal the source of their net and duplicate sinks, since they can never change the cost or the I/O usage.

3. Data structures and incremental evaluation

The hypergraph is stored in CSR form: for every net its weight, source and sink list; for every node the list of incident nets. The partition state (Refiner) keeps, for each net, the number of sinks in every FPGA. Nets with at most 8 sinks use a sparse list of (FPGA, count) pairs (at most min(#sinks, K) entries), larger nets a dense array of size K; |O(e)| is kept explicitly. Additionally the state stores the I/O usage and the two loads of every FPGA, the current cost, the amount of signals over missing links and the total I/O overflow.

Moving node v from FPGA a to b is evaluated net by net:

  • v is a sink of e (source in s): a leaves O(e)\{s} iff its count drops to 0 (and a≠s); b enters iff its count was 0 (and b≠s). The cost changes by w·(D(s,b) − D(s,a)) for the parts that apply; I/O changes by ±w on a, b, and on s if the net switches between cut and uncut. O(1) work for dense nets.
  • v is the source of e: sink counts are unchanged; the cost becomes w·Σf∈O(e) D(b,f) instead of w·Σf∈O(e) D(a,f), and the I/O usage of a, b (and of O(e) if the net becomes cut/uncut) is updated. O(|O(e)|) work.

The I/O deltas are accumulated in a small scratch array, from which the change of the overflow term is computed. The same template routine either only evaluates a move or also commits it, which guarantees that evaluation and update are consistent. A randomised test comparing the incremental state with a full recomputation after hundreds of thousands of random moves was used to validate it.

4. Algorithm

4.1 Multilevel partitioning

Coarsening. Nodes are visited in random order; an unclustered node u joins the neighbouring cluster C maximising the heavy-edge rating with weight penalty [2] r(u,C) = Σe∋u,C (w(e)/(|e|−1)) / (size(u)·size(C)), where nets with more than 64 pins are ignored (e.g. clock-like nets with 594 167 sinks in public5). A cluster may contain at most 6 % of the smallest type-1 capacity and 6 % of the smallest type-2 capacity, which keeps the coarse problem packable. Contraction drops sinks that fall into the cluster of the source, merges duplicate sinks, removes empty nets and merges identical nets (same source and sink set) by adding their weights — this preserves both the TLC and the I/O usage of every partition exactly. Coarsening stops at 24·K nodes or when a level shrinks by less than 3 %.

Initial partitioning. On the coarsest level 12 candidates are created and the best is kept: (a) a topology-aware greedy growing — nodes are visited in BFS order and each is put into the FPGA with free capacity that minimises the link cost to its already placed neighbours (ties: most free capacity), which grows regions and puts spill-over into cheaply linked FPGAs; (b) random capacity-feasible assignments. Each candidate is improved by greedy K-way refinement trying every FPGA.

Uncoarsening. The partition is projected level by level; on each level greedy refinement passes are applied: boundary nodes (nodes with at least one cut incident net) are visited in random order and moved to the best capacity-feasible FPGA among those that contain their neighbours, if that strictly decreases J.

4.2 Multilevel simulated annealing

Greedy refinement gets stuck quickly, mainly because FPGAs become full. The main optimiser is therefore simulated annealing [3] embedded in a multilevel framework [4]:

  1. From the current partition a new hierarchy is built with the restriction that only nodes of the same FPGA may be clustered. Thus every level represents exactly the same partition, and the coarsest level has at most Ntop nodes (5000 by default; also n/3 and n/8 in other attempts, see 4.3).
  2. Levels are annealed from coarsest to finest. The level l gets a share of the remaining time proportional to nl−1, i.e. coarse levels get most of the time. The initial temperature is t0 = τ·(mean positive Δ of random moves) with τ = τtop on the coarsest level and τ·0.05 per level below (hot on coarse levels, nearly greedy on fine levels); the temperature decreases geometrically in time down to 0.05, after which a greedy pass finishes the level.
  3. Moves. A boundary node v is drawn uniformly (the boundary list is rebuilt about 100 times per run). The target b is a random FPGA containing a neighbour of v; with probability 1/16 any FPGA is chosen, so that empty or far FPGAs can also be populated. If b has no room for v, a swap is attempted with a random boundary node u of b that fits into a (per-FPGA boundary pools make this O(1)). The Metropolis rule is applied to the exact combined delta.
  4. The best state (lexicographic key of Section 2) is tracked lazily: only the nodes moved since the last new best are recorded, so saving a new best costs time proportional to the number of moves made since the previous one.

Swap moves turned out to be essential: in public1 about 98 % of single moves are blocked by capacity, and adding swaps alone reduced the annealed TLC from 1377 to 238.

4.3 Parallel multi-start and time management

The default time budget is 250 s of the 300 s limit (minus a margin for output). W = min(4, #cores) worker threads (fewer for very large inputs, to bound memory) repeatedly run attempts = multilevel partitioning + multilevel annealing. The attempt length is max(3 s, 2 ms·N): small inputs (N = 600) get dozens of restarts per worker, inputs with ≥ 125 000 nodes a single long attempt. Attempts are diversified by τtop ∈ {2, 1, 4, 0.5} and by Ntop ∈ {5000, n/3, n/8}: no single setting was best on all instances (e.g. public2 needs coarse-level annealing even though it has only 1600 nodes, whereas public1 is solved best without coarsening). Workers share only the best solution, protected by a mutex; the hypergraph is read-only. The program is deterministic apart from thread timing.

5. Results

Machine used for the experiments: 4-core Linux container, g++ 13.3, -O3. TLC values were verified with the provided checker (all solutions legal).

6. Complexity

Let P be the number of pins. Parsing, coarsening (one level) and contraction run in O(P log P) (sorting of sink lists and net hashes); memory is O(P + mK) in the worst case for the pin counters (only nets with more than 8 sinks use K counters). A move evaluation costs O(Σe∋v c(e)) with c(e) = 1 for nets where v is a sink and c(e) = |O(e)| ≤ K where it is the source. Peak memory for the largest public instance is reported above and far below the 8 GB limit.
